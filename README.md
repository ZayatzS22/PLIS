# PLIS — датчики линейных направляющих / Xilinx SP605

Репозиторий исследовательского проекта по разработке собственной высокоточной системы измерения положения каретки для линейных направляющих предприятия.

> **Текущий экспериментальный статус:** реальные сигналы от разрабатываемого датчика/катушек на вход измерительной цепочки пока не подавались. Все проведённые до настоящего момента проверки были тестовыми. Поэтому форма, частота, амплитуда и период реальных SIN/COS, пригодность текущего режима AD7357 и сам алгоритм положения ещё не подтверждены физическими измерениями. Подробно: [`docs/CURRENT_STAND_STATUS.md`](docs/CURRENT_STAND_STATUS.md).

## Что выяснено после подробного разбора PDF

Есть несколько принципиальных вопросов, которые нужно решить до реализации алгоритма положения в FPGA. Пока это вопросы для будущих реальных испытаний, а не выводы по уже измеренному датчику:

1. Bosch указывает физический шаг шкалы 1000 мкм, но период аналогового A/B — 40 мкм. Во внутренней модели ОМЗ и геометрический, и полезный период пока приняты равными 1 мм. Реальный электрический период нашего датчика ещё не измерялся.
2. Внутренняя презентация предполагает работу с несущей около 625 кГц и рекомендует ADC 6,25 MSPS. AD7357 имеет максимум 4,2 MSPS, а текущий MAIN использует SCLK около 613,6 кГц. Так как реальные сигналы на ADC пока не подавались, по этому сравнению нельзя пока делать вывод о пригодности или непригодности текущего режима.
3. Необходимо выяснить по схеме и будущим измерениям, что физически будет поступать на AD7357: сырая высокочастотная несущая с катушек или уже демодулированные SIN/COS после аналогового тракта.
4. Нужно аппаратно подтвердить bit alignment 14-битного AD7357 в текущем `adc_receiver.v` до окончательной фиксации ADC→DAC и дальнейшей математики.

Главная последовательность ближайших работ:

```text
уточнить analog signal chain
→ проверить генератор/катушки осциллографом
→ проверить AD7357 timing/bit alignment на известном входе
→ впервые подать реальные сигналы датчика
→ записать raw A/B
→ определить реальный период и квадратуру
→ разработать алгоритм на ПК
→ после проверки перенести нужные блоки в FPGA
```

Все новые существенные технические выводы фиксируются в Markdown вместе с датой, версией кода/commit и типом подтверждения: `DOC`, `CALC`, `TEST` или `REAL`.
