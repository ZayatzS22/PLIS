# Пошаговый поиск источника шумов на стенде PLIS

Дата: 10.09.2026.

Цель: не «убрать шум на глаз», а локализовать, на каком участке цепочки он появляется.

## 1. Общая цепочка

```text
чувствительная часть / катушки
        ↓
аналоговая плата: усиление / формирование сигнала
        ↓
аналоговые входы AD7357
        ↓
AD7357: аналог → цифровой код
        ↓
FPGA SP605 / adc_receiver
        ↓
RAW A/B
        ↓
UART → ПК
        └→ DAC MAX5853 → осциллограф
```

Главный принцип диагностики: двигаться по этой цепочке и искать первую точку, где сигнал из стабильного становится нестабильным.

## 2. Подготовка перед измерениями

1. Жёстко зафиксировать гребёнку/тестовую металлическую структуру.
2. Не держать чувствительную часть рукой.
3. Не двигать провода во время измерения.
4. Использовать один и тот же режим стенда для всех сравнений.
5. На осциллографе настроить trigger, чтобы форма не «ехала» по экрану.
6. Для каждого измерения записывать:
   - точку измерения;
   - канал;
   - V/div;
   - time/div;
   - Vpp основного сигнала;
   - приблизительную толщину/разброс линии;
   - есть ли периодические выбросы;
   - меняется ли картина от прикосновения к проводам.

## 3. Самая первая точка: прямо перед AD7357

Сначала надо посмотреть два аналоговых сигнала, которые физически входят в AD7357.

Почему именно здесь: эта точка делит систему на две части.

```text
если уже перед ADC шумно
→ проблема до ADC: катушки / аналоговый тракт / питание / земля / наводки

если перед ADC чисто, а RAW на ПК шумный
→ смотреть ADC / reference / timing / FPGA capture
```

Важно: AD7357 имеет дифференциальные входы. Желательно знать, где у каждого канала `VIN+` и `VIN-`. Если есть возможность, смотреть разность двух входов, а не только один провод относительно земли.

## 4. Как понять, что сигнал шумит

При неподвижном стенде и нормальном trigger одна и та же форма должна повторяться почти по одной траектории.

Подозрительные признаки:

- линия на экране толстая/«мохнатая»;
- вершина сигнала гуляет вверх-вниз;
- нулевые пересечения заметно плавают;
- появляются случайные иглы/выбросы;
- амплитуда меняется без движения;
- форма меняется при касании проводов;
- появляются устойчивые пачки помех с определённым периодом.

Не путать с плохим trigger: если вся форма целиком едет вправо-влево, сначала исправить синхронизацию осциллографа.

## 5. Затем идти назад по аналоговой части

Если на входе AD7357 уже шумно, двигаться от ADC в сторону катушек.

Порядок:

```text
точка A: вход AD7357
↓
точка B: выход последнего усилителя перед ADC
↓
точка C: выход предыдущего аналогового каскада
↓
точка D: сигнал ближе к катушкам
```

Смысл:

```text
D — чисто
C — чисто
B — шумно
A — шумно
```

Тогда проблема появилась между C и B или непосредственно в каскаде B.

## 6. Отдельно проверить питание

Проверять не 220 В, а низковольтные линии прямо на платах.

Для AD7357 ориентиры из datasheet:

```text
VDD ≈ 2.5 В
VDRIVE ≈ 2.25…3.6 В
REFA / REFB ≈ 2.048 В, если используется внутренняя опора
```

Сначала мультиметром проверить постоянный уровень. Затем осциллографом посмотреть, нет ли поверх него:

- заметной ряби;
- высокочастотных выбросов;
- синхронных импульсов с частотой FPGA/ADC;
- провалов при переключении цифровой части.

Особенно важны `REFA/REFB`: если опорное напряжение шумит, цифровой масштаб ADC тоже будет нестабилен.

## 7. Проверить землю

Нужно выяснить:

- где объединены земли аналоговой платы, ADC, SP605 и БП;
- нет ли нескольких путей возвратного тока;
- не образует ли подключение осциллографа дополнительную земляную петлю;
- не проходит ли цифровой ток по той же земле, что чувствительный аналоговый сигнал.

Практический признак проблемы земли: форма заметно меняется при подключении второго прибора, USB/UART, другого БП или дополнительного щупа.

## 8. Проверить синхронизацию выборки ADC

Нужно одновременно посмотреть:

```text
CH1 — SIN перед AD7357
CH2 — COS перед AD7357
CH3 — CS AD7357
CH4 — takt_p / adc_clk
```

Для AD7357 падающий фронт `CS` фиксирует входные значения обоих каналов и запускает преобразование.

Надо понять: в какой точке ВЧ-сигнала происходит это событие.

Если выборка приходится на вершину/плоский участок, маленькая временная ошибка мало меняет амплитуду.

Если выборка приходится на крутой склон, небольшой джиттер или задержка превращается в заметный разброс измеренного кода.

Это один из основных кандидатов, если после перепайки проводов шум почти не изменился.

## 9. Контрольный тест AD7357

Это один из самых полезных экспериментов.

Вместо сигнала с аналогового тракта подать на вход ADC заведомо стабильный тестовый уровень, соблюдая допустимый дифференциальный/common-mode режим AD7357.

Далее смотреть RAW A/B на ПК.

Результат:

```text
стабильный тестовый вход + стабильные RAW
→ ADC + цифровой приём в целом работают
→ главный шум находится до ADC

стабильный тестовый вход + RAW сильно прыгают
→ смотреть VREF / питание / timing / ADC / разрядное выравнивание / FPGA capture
```

## 10. Проверка цифровых кодов

AD7357 — 14-битный ADC.

Полезный диапазон кода:

```text
0 … 16383
```

Около нулевого дифференциального входа ожидается район середины диапазона:

```text
~8192
```

При неподвижном стенде важно записать минимум 100–1000 последовательных значений A и B.

Для каждого канала посчитать/записать:

```text
mean
min
max
peak-to-peak = max - min
std
```

Если ПК показывает числа существенно выше 16383, нужно отдельно выяснить формат отображения: это может быть 16-битное слово со сдвигом, преобразованное значение или другая обработка, а не прямой 14-битный код AD7357.

## 11. Проверка наводок от цифровой части

Если аналоговый сигнал загрязнён импульсами, сравнить их период с:

- `adc_clk / takt_p`;
- `CS`;
- DAC clock/data;
- UART;
- системным тактом FPGA.

По возможности временно отключать необязательные блоки и смотреть, меняется ли шум.

Особенно полезно сравнить:

```text
DAC включён / выключен
UART подключён / отключён
ПК по USB подключён / отключён
разные БП
```

Если шум резко меняется при отключении конкретного цифрового узла, это сильная зацепка.

## 12. Что значит недавняя перепайка стенда

Если раньше были длинные/болтающиеся провода и временные соединения, перепайка могла уменьшить:

- плохие контакты;
- микрофонный эффект и механические изменения;
- площадь петель;
- часть внешних наводок.

Но если после перепайки шум почти не изменился, это важный диагностический результат. Тогда вероятные причины смещаются в сторону:

- аналогового каскада;
- питания и reference;
- общей земли;
- неправильного драйва входов ADC;
- синхронизации выборки;
- цифровых наводок;
- механики самого чувствительного узла.

## 13. Что НЕ делать первым

Не начинать сразу с сильного цифрового фильтра.

Причина: фильтр может сделать красивый график, но скрыть аппаратную проблему и добавить задержку измерения.

Правильный порядок:

```text
локализовать источник
↓
устранить крупную аппаратную проблему
↓
измерить остаточный шум
↓
подобрать цифровую фильтрацию
↓
только потом atan2 / phase / coordinate
```

## 14. Минимальный сценарий на встрече

Если времени мало, спросить и проверить четыре вещи:

1. После перепайки шум изменился количественно или только «на глаз»?
2. Шум виден уже прямо на входах AD7357?
3. Как выглядят `REFA/REFB` и питание AD7357 на осциллографе?
4. Где относительно SIN/COS находится падающий фронт `CS`?

Если ответы на эти четыре вопроса получить, круг поиска уже сильно сузится.

## 15. Что записывать после каждого теста

Пример записи:

```text
Точка: вход AD7357, канал A
Гребёнка: неподвижна
V/div: 200 mV
Time/div: 1 us
Vpp основного сигнала: 0.9 V
Шум/разброс линии: ~30 mV p-p
Выбросы: есть, периодические
Связь с CS: совпадают с фронтом CS / не совпадают
При касании проводов: меняется / не меняется
```

Такие записи гораздо полезнее формулировки «шум большой».
