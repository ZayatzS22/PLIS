Дата фиксации: 01.09.2026.

Источник: файл `sin_gen(1).v`, который был передан непосредственно с пояснением, что именно этот `sin_gen` загружен в плату SP605 во время текущих испытаний стенда.

Статус: **TEST / подтверждено пользователем как загруженный top-level**.

# 1. Сопоставление с GitHub

Переданный `sin_gen(1).v` по функциональной логике совпадает с текущим:

```text
Main/sin_gen/sin_gen.v
```

В частности совпадают:

- `SYNC_MARKER = 8'hA5`;
- формирование `out_takt` делителем от системного `clk`;
- подключение `adc_receiver`;
- передача сырых `adc_out_a/adc_out_b` в UART;
- четыре байта на пару A/B;
- маркер через 128 кадров;
- подача `adc_out_a[13:4]` и `adc_out_b[13:4]` на `max5853_dual_cntrl`.

Следовательно, наблюдаемые сейчас осциллограммы и видео нужно связывать именно с этой версией top-level.

# 2. Что делает загруженный `sin_gen.v`

## 2.1 Тактирование аналоговой части и ADC

`out_takt` формируется переключением состояния при `counter == 21`:

```verilog
if (counter == 6'd21) begin
    counter <= 0;
    out_takt <= ~out_takt;
end
```

При системной частоте 27 МГц полный период `out_takt` составляет 44 системных такта, то есть приблизительно:

```text
27 MHz / 44 ≈ 613.6 kHz
```

Далее этот сигнал одновременно назначается:

```verilog
assign adc_clk = out_takt;
assign takt_p  = out_takt;
assign takt_n  = ~out_takt;
```

То есть FPGA синхронно формирует такт для внешнего аналогового тракта и такт, используемый интерфейсом ADC.

# 3. Что происходит с данными ADC

Top-level принимает две цифровые линии:

```verilog
input adc_data_a,
input adc_data_b
```

и передает их в отдельный модуль:

```verilog
adc_receiver adc_receiver_inst(...)
```

Результаты этого модуля:

```verilog
wire [15:0] adc_out_a;
wire [15:0] adc_out_b;
```

Сам `sin_gen.v` **не выполняет математическую обработку SIN/COS**.

В нем отсутствуют:

- `atan` / `atan2`;
- CORDIC;
- вычисление фазы;
- нормализация SIN/COS;
- коррекция offset;
- коррекция амплитуд;
- phase unwrap;
- расчет координаты.

---

# 4. Что передается по UART

При `adc_ready` top-level просто копирует результаты ADC:

```verilog
adc_a <= adc_out_a;
adc_b <= adc_out_b;
```

и передает их четырьмя байтами:

```text
A[7:0]
A[15:8]
B[7:0]
B[15:8]
```

То есть на уровне `sin_gen.v` UART несет **сырые 16-битные слова A/B**, а не рассчитанный угол.

Это важно при интерпретации текущего графика на ПК: если программа не выполняет дополнительную математику самостоятельно, то график строится из raw A/B.

---

# 5. Что сейчас подается на DAC

В загруженном top-level присутствует экспериментальная связь ADC -> DAC:

```verilog
.data_a(adc_out_a[13:4]),
.data_b(adc_out_b[13:4]),
```

Таким образом два 10-битных входа контроллера MAX5853 получают выбранные биты из двух результатов AD7357.

Этот участок был добавлен для текущей задачи вывода значений ADC на двухканальный DAC.

Bit alignment `[13:4]` по-прежнему должен окончательно подтверждаться реальным измерением/логическим анализатором, так как корректность положения 14 полезных бит зависит от фактического захвата последовательного слова в `adc_receiver.v`.

---

# 6. Где могла находиться старая математика с арктангенсом

Поскольку в данном `sin_gen.v` арктангенса нет, ранее показанная коллегой экспериментальная математика могла находиться:

1. в другой/старой версии `adc_receiver.v`;
2. в отдельном модуле, который не входит в текущий репозиторий;
3. в другой версии `sin_gen.v`;
4. в принимающей программе на ПК.

Текущий репозиторий `Main/sin_gen/adc_receiver.v` также содержит только прием и сборку последовательных данных, без `atan/atan2`.

Следовательно, старая версия алгоритма пока считается **утраченной/не добавленной в Git** до получения исходников от коллеги.

---

# 7. Связь с текущими видео и осциллограммами

На момент съемки текущих материалов SP605 работает с top-level без математического вычисления положения.

Поэтому наблюдаемая реакция стенда при перемещении тестовой металлической структуры относится к этапу:

```text
физический/тестовый отклик
-> ADC
-> raw A/B
-> UART и/или DAC
```

а не к готовому результату `atan2` или координате.

Это важная контрольная точка: текущие материалы можно использовать для изучения raw-тракта до внедрения алгоритма определения положения.
